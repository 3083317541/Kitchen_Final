# 美术资源替换指南

本文档说明如何把白模换成你自己的美术资源。**核心原则：所有美术都通过数据资产的字段接入，不需要改动任何游戏逻辑代码。**

---

## 1. 唯一的接入口：ScriptableObject 字段

游戏逻辑只认识配置数据；模型、材质、动画都是可选的"皮"。每个可替换对象都有一组 **Art Replacement** 字段，留空就用白模，填上就用你的资源。

### 厨具 — `Assets/_Game/Data/Cookers/Cooker_*.asset`

| 字段 | 作用 |
|---|---|
| `View Prefab` | 你的厨具模型预制体。**填上后内置白模完全不再生成** |
| `Body Material` | 主体材质（白模用它，也可用于你的模型） |
| `Accent Material` | 强调色材质（工作台的边框/状态指示） |
| `Body Color` / `Accent Color` | 没有材质时的纯色回退 |
| `Body Size` | 白模尺寸。**不影响格子占用**，占用永远是 1 格 |

价格与加工时间也在同一个资产上（`Price`、`Duration`、`Tick Interval`、`Required Ticks`），改这些不需要动代码。

### 食材 / 成品 / 盘子 — `Assets/_Game/Data/Ingredients/Item_*.asset`

| 字段 | 作用 |
|---|---|
| `View Prefab` | 世界中的物品模型（放在厨具上/待取产出） |
| `View Material` | 物品材质 |
| `View Color` / `View Scale` | 白模的颜色与大小 |
| `Icon` | **UI 图标**（当前 HUD 用文字，已预留此字段给图标化 HUD） |

### 员工 — `Assets/_Game/Scripts/View/StaffView.cs`

员工白模由 `ViewFactory.CreateStaffView()` 运行时构建。要换成美术模型：

1. 做一个预制体，根节点挂 `StaffView` 组件。
2. 把模型作为子物体，**给它一个名为 `Accent` 的子渲染器**（可选，用于选中高亮；找不到就跳过）。
3. 把该预制体赋给 `StaffView.Model Prefab`。
4. 或者在 `ViewFactory.CreateStaffView()` 里 `Instantiate` 你的预制体——这是唯一一处员工外观来源。

`StaffView` 上可调的还有 `Body Material`、`Head Material`、`Selection Material`、`Selection Color`（脚下选中圈）、`Body Height`、`Body Radius`。

### 动画

- `StaffView` 会自动 `GetComponentInChildren<Animator>()`，并在选中时设置布尔参数 `"Selected"`。
  在 Animator 里建同名参数即可接上；没有 Animator 也不报错。
- 行走表现目前是位置插值（`StaffManager` 把模型移动到格子中心）。要换成走/跑动画，
  在 `StaffView` 里加 `SetMoving(bool)` 并设置 `animator.SetBool("Moving", ...)`，
  由 `StaffManager.Tick` 调用——**改动只在视图层，游戏逻辑不受影响**。

### 环境 / 地板 / 网格

| 文件 | 字段 |
|---|---|
| `Scripts/View/GridView.cs` | `Floor Prefab`（地板模型/预制体）、`Floor Material`、`Cell Material`、`Valid Highlight Material`、`Invalid Highlight Material`、`Floor Color`、`Cell Color`、`Valid Color`、`Invalid Color` |
| `Scripts/View/PlacementPreview.cs` | `Ghost Prefab`（建造虚影模型）、`Valid Material`、`Invalid Material`、`Ghost Height`、`Ghost Footprint` |

### 全部白模材质集中地

`Scripts/View/Whitebox.cs` 顶部的调色板常量（`FloorColor`、`MetalColor`、`GridCellColor`、
`StaffBodyColor`、`StaffSelectedColor` …）是白模的单一配色来源。

材质分两类，替换时请注意：
- **Solid**（`SolidMaterial`）→ 用 `Standard` 受光着色器，用于有体积的物体。
- **Overlay**（`OverlayMaterial` / `Decal`）→ 无光照透明，用于地面贴花（格子、高亮、虚影、选中圈）。

## 2. 操作步骤

### 换厨具模型

1. 把你的模型做成预制体，放在 `Assets/_Game/Prefabs/Cookers/` 下。
2. **模型正面朝 +Z**，底部对齐 Y=0，**横向不要超过 1 格**（默认 2 个单位）。
   > 尺寸超了不会破坏规则（碰撞盒与格子占用固定为 1 格），但视觉上会压到相邻格子。
3. 打开 `Assets/_Game/Data/Cookers/Cooker_chopping_station.asset`，
   把预制体拖到 **View Prefab**。
4. 直接 Play。不需要重新生成场景——运行时读取配置。

### 换员工模型

1. 预制体放 `Assets/_Game/Prefabs/Staff/`。
2. 根节点加 `StaffView` 组件，模型作为子物体。
3. 在 `ViewFactory.CreateStaffView()` 中实例化你的预制体（或给 `StaffView.Model Prefab` 赋值）。
4. 想让选中圈用美术资源，给 `Selection Material` 赋值。

### 换地板与网格

在场景里选中 `World/GridRoot/GridView`（运行时生成），或改 `GridView` 的默认字段值后重新生成场景。
若要长期生效，推荐**在中生成器里赋值**：编辑
`Assets/_Game/Editor/KitchenSceneBuilder.cs` → `CreateWorld()`，在创建 `GridRoot` 后
把 `GridView` 的 `floorPrefab` 等字段写入 `SerializedObject`。

### 换 UI 皮肤与字体

- UI 由 `Assets/_Game/Editor/KitchenUIBuilder.cs` 以布局组方式生成（面板锚定四边，中间留空给厨房）。
  改配色改文件顶部的 `PanelColor` / `ButtonColor*` / `TextColor` 等常量。
- 改字体：替换 `Assets/_Game/Art/Fonts/KitchenHudCJK.asset`（由生成器从系统字体创建，
  `Assets/_Game/Art/Fonts/` 下同时保存了源字体文件）。把该资产换成你的 TMP 字体资产即可，
  `KitchenUIBuilder` 会自动使用它。

## 3. 规则边界（替换美术时不要踩）

这些是刻意设计的约束，保证换皮不会改变玩法：

- **模型缩放不决定格子占用。** 厨具碰撞盒与 `GridData` 占用固定为 1 格（`CookerView.MaxFootprint`）。
- **动画不驱动加工规则。** 进度在 `CookerRuntime` 里，由 `WorkManager` 统一推进；动画只是表现。
- **美术预制体不管理订单与库存。** 库存唯一入口是 `InventoryManager`。
- **视图不查询游戏状态做决策。** `CookerView` / `StaffView` / `GridView` 只渲染被告诉的状态。

---

## 4. 验证替换是否成功

生成并跑一次验收：

```
Kitchen/3. Generate Everything        （菜单）
Kitchen/5. Verify Acceptance Criteria （菜单）
```

报告写在 `Logs/acceptance_report.json`，其中和美术相关的检查：

| 检查项 | 含义 |
|---|---|
| `models_have_3d_volume` | 厨具/员工由足够多的可见部件组成 |
| `models_fit_their_cell` | 厨具没有超出自己那一格 |
| `models_cast_shadows` | 模型会投影（说明是受光的 3D 物体） |
| `views_present` | 每个厨具与员工都有激活的视图 |
| `ui_no_panel_overlap` | HUD 六个面板互不重叠 |
| `ui_text_fits` | 每个标签的文字宽度放得下 |
| `ui_labels_have_font` / `ui_font_has_glyphs` | 字体可用且所需字形齐全 |

换成你自己的美术后，这些检查应当继续通过（`models_fit_their_cell` 例外：如果你的美术刻意跨格，
那说明你需要同时改 `CookerView.MaxFootprint` 与网格占用逻辑，那属于玩法改动，不在美术替换范围内）。
